# cinezo

Order snacks from your cinema seat. Each seat has its own QR sticker, so the order is always delivered to that seat. Node 22.5+, Express and built-in SQLite (no native build), with live updates (SSE) to the owner dashboard.

## How seats work
Stickers are made in **Owner dashboard → Seat QR**. Each QR link looks like `#seat-1-F-5-<signature>`. The signature is generated by the server from your `SECRET`, so a customer can't change the seat or invent one. `/api/pay` rejects any order without a valid signature, and the delivery seat is always the signed one. Stick the QR on the back of the chair in front.

## Reports
**Owner dashboard → Reports**: Today (hourly), last 7 days and last 30 days. Shows orders, revenue, average order, cancellations, an orders-over-time chart and top items. Day boundaries use IST by default; set `TZ_OFFSET_MIN` for another zone.

## Run locally
    npm install
    OWNER_PIN=1234 SECRET=any-long-random-text OPEN_SEATS=1 npm start
    npm test

Open http://localhost:3000 (customer) and http://localhost:3000/#owner (owner). `OPEN_SEATS=1` accepts unsigned seat links so the built-in demo seats work. Never set it in production.

## Deploy on Render
1. Push this folder to GitHub.
2. Render → New → Web Service. Build: `npm install`. Start: `npm start`.
3. Environment: `OWNER_PIN` (not 1234) and `SECRET` (long random text). In production the server refuses to start without them.
4. Add a Disk mounted at `/data` and set `DB_PATH=/data/seatserve.db` so orders survive restarts.
5. Open `https://<your-app>.onrender.com/#owner`, go to Seat QR, generate and print the stickers. Changing `SECRET` invalidates every printed sticker.

- SQLite runs in WAL mode with an index on order time; the live board loads only today's orders plus any still open.
- `index.html` is pre-gzipped and served with an ETag.
## Payments: demo now, Razorpay when approved

Until you set Razorpay keys, checkout uses the **demo UPI** (any UPI ID works, `fail@demo` fails, `pending@demo` waits). Nothing to change in the code to switch: add two environment variables and restart.

1. Test first with your Razorpay keys from the Razorpay dashboard:
   `RAZORPAY_KEY_ID=...` and `RAZORPAY_KEY_SECRET=...`.
2. In the Razorpay dashboard add the webhook URL `https://<your-app>.onrender.com/api/razorpay/webhook` and enable the *Payment Captured* event.
3. Place a test order. The customer enters a mobile number, pays in Razorpay's window, and the order appears on the board only after Razorpay confirms `captured` for the full amount.
4. For real money, use your production keys. Optionally set `PUBLIC_URL=https://<your-domain>` if the app sits behind a custom domain.

How it works: `/api/pay` prices the cart on the server and creates a pending order plus a Razorpay order. The browser opens the Razorpay window, then calls `/api/pay/verify` with the Razorpay signature. The signed webhook does the same check in the background, so a closed tab or dropped network never loses a paid order. Both paths are idempotent. Unpaid orders are deleted after an hour and never show on the board or in reports.

## Operations
- Owner sessions are signed and expire after 12 hours. Login and "not received" reports are rate limited.
- A SQLite backup is written at startup and daily to `backups/` next to the database (last 7 kept; set `BACKUP_DIR` to change). On Render, keep it on the same disk or copy it off.
- SQLite runs in WAL mode with an index on order time; the live board loads only today's orders plus any still open.
- `index.html` is pre-gzipped and served with an ETag.
- `npm test` runs 7 tests, including the full Razorpay flow against a mocked Razorpay API.
